## Rules that apply to everyone
1. **Do NOT run Gradle** (several agents work in the same project at once; builds would collide). The lead compiles and fixes errors afterwards. So be exact: read the foundation files listed below and use their real signatures. Re-read your own files for unresolved imports / wrong parameter names before finishing.
2. **Only touch the files/folders you own** (listed in your assignment). Never edit foundation files (`core/**`, `OrbitApp.kt`, `AppDestination.kt`, `strings.xml`, ...). If you need something missing in `core`, put a private helper in your own feature package and tell the lead in your final report.
3. **Delete your stub files** in `feature/stubs/` (named in your assignment) — the real screens replace them. Keep the module val names and screen signatures EXACTLY as given.
4. **No hardcoded user-visible strings.** Every string goes in `res/values/strings_<feature>.xml`, with Urdu in `res/values-ur/strings_<feature>.xml` and Spanish in `res/values-es/strings_<feature>.xml` (same keys, same file names, real translations — Urdu must be proper Urdu script). Prefix every key with your feature prefix to avoid collisions. Shared keys already available (do not redefine): `app_name, app_brand, app_tagline, nav_*, action_back/save/cancel/delete/edit/add/done/close/search/undo/archive/unarchive/retry/continue/skip/next/clear/more_options/discard/keep_editing, state_loading, error_generic, priority_low/medium/high/urgent, status_todo/in_progress/completed/archived/active/on_hold, weekday_mon..weekday_sun`. Use `pluralStringResource` / `<plurals>` for counts. Use formatted args (`%1$s`, `%1$d`), never string concatenation of translated pieces.
5. **RTL**: use start/end (never left/right), `Icons.AutoMirrored.*` for directional icons, `Arrangement.Start/End`, `padding(start=..)`. Layouts must work for Urdu.
6. **Accessibility**: every icon-only button has a `contentDescription` (from string resources); touch targets >= 48dp; do not rely on colour alone (pair with text/icon); decorative icons `contentDescription = null`; use `Modifier.semantics`/`clearAndSetSemantics` where it helps TalkBack; text uses `sp` (typography from `MaterialTheme.typography`) so large fonts work; layouts must not clip at 200% font scale (use `heightIn(min=..)`, wrapping text, scrollable columns).
7. **Responsive**: phone and tablet. For wide screens (`LocalConfiguration.current.screenWidthDp >= 600`) constrain content width (`Modifier.widthIn(max = 720.dp)` centered) or use two columns where it makes sense.
8. **Architecture**: MVVM. `ViewModel` (androidx) per screen in the feature package, exposing an immutable `UiState` data class via `StateFlow` (`stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), initial)`), with explicit loading / empty / error handling. Business logic in ViewModels/use-case-like pure functions, NOT in composables. Composables take state + callbacks. Collect with `collectAsStateWithLifecycle()`. Register ViewModels in your feature's Koin module: `viewModel { XViewModel(get(), ...) }` (`org.koin.core.module.dsl.viewModel`) with parameters via `viewModel { (id: String?) -> ... }` and obtain in composables with `koinViewModel(parameters = { parametersOf(id) })` (`org.koin.compose.viewmodel.koinViewModel`, `org.koin.core.parameter.parametersOf`). Because Navigation 3 uses a ViewModel store per entry, give the ViewModel a `key` when it takes parameters: `koinViewModel<XViewModel>(key = "task_$id", parameters = { parametersOf(id) })`.
9. **Never log user content** (no `Log.*` of titles/notes/etc.). No new permissions, no INTERNET.
10. **Dates**: use `core/common` helpers (epoch-day Int for dates, minute-of-day Int for times, epoch millis for instants). "Today" comes from `todayFlow()` in ViewModels (re-emits at midnight) — never cache `LocalDate.now()` in a ViewModel field. Use `DateFormats.*` to format. Use `TaskRules.*` for overdue/today/upcoming.
11. **UX**: 8dp spacing from `Spacing`, cards via `OrbitCard`, empty states via `EmptyState`, loading via `LoadingState`, errors via `ErrorState`, destructive actions behind `ConfirmDialog` (verb-first labels like "Delete project", never "OK"), top bars via `OrbitTopBar`, primary buttons are Material 3 `Button`/`FloatingActionButton`. Subtle animation only (`animateContentSize`, `AnimatedVisibility`, `animateItem()` in lazy lists). Lazy lists always pass `key =` and `contentType =`. Bottom padding on scrolling lists should leave room for FABs. Each screen has its own `Scaffold` (containerColor = background); the bottom navigation bar is hosted by the outer app shell for tab screens (Home, Tasks, Projects, Calendar, More), which already consumes the bottom inset.
12. Keep files focused (< ~400 lines each). Split composables into files by responsibility. No TODO placeholders, no fake data, no fake statistics: every number shown comes from the database.
13. After you finish: re-read every file you created once, check imports/signatures against the foundation, then report: files created, any foundation gaps or questions, string keys for anything the lead must know, and anything not finished.
