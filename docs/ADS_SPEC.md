# ORBIT ads, consent, remote config and offline logic — implementation brief

## Product decision (from the app owner, in chat)
The owner explicitly wants ads in ORBIT, structured like the reference app PrankHub: native ads on the Language screen, on the Onboarding screens and in the Exit sheet, a banner like PrankHub's inner banner, interstitials with load/show logic and capping, the splash/initialization logic driving ad loading, a remote (Firebase Remote Config) layer, and an internet/no-internet logic. **Debug builds must show Google TEST ads only.** This replaces the earlier "no ads / no INTERNET" product rule; therefore all copy that claims "no ads", "works without internet / never connects" or "no network permission" must be corrected (Privacy, About, Premium, Onboarding page 4, splash footer, README) — the app's USER DATA (tasks, notes, habits, goals, projects) still never leaves the device; the network is used only for ads, the consent form and remote config.

## Rules
1. **Test vs release**: `BuildConfig.DEBUG` → Google public sample ids ONLY. AdMob app id (debug): `ca-app-pub-3940256099942544~3347511713`; adaptive banner `ca-app-pub-3940256099942544/9214589741`; interstitial `ca-app-pub-3940256099942544/1033173712`; native `ca-app-pub-3940256099942544/2247696110`; app open `ca-app-pub-3940256099942544/9257395921`. Release ids come from Gradle properties (`gradle.properties` / `~/.gradle/gradle.properties`): `orbit.admob.appId`, `orbit.ad.banner`, `orbit.ad.native`, `orbit.ad.interstitial`, `orbit.ad.appOpen`. If a release id is missing, ads for that placement are disabled at runtime (no requests) and the release build prints a loud Gradle warning; a release BUNDLE/APK build must FAIL (`GradleException`) when `orbit.admob.appId` is missing or equals the sample id (so a test id can never ship). Provide ids to code via `BuildConfig` string fields and the app id via `resValue("string","admob_app_id", …)` referenced from the manifest meta-data `com.google.android.gms.ads.APPLICATION_ID`.
2. **Policy safety (AdMob/Play)**: native ads always show the "Ad" badge and the advertiser/headline/body/CTA/icon/media in a clearly separated container with ≥ 16dp gap from the app's own buttons; never place ads over or immediately next to primary buttons (Next, Done, Continue, Save); ads never overlap content or the floating bottom bar; no ads on Splash content, on Premium screens, on the Feedback screen, in notification flows; interstitials only at natural transition points, never mid-task/typing, with capping; no auto-clicking, no incentivising clicks, no fake close buttons; children-directed flags not set (app is general audience); the UMP consent flow (GDPR/CCPA) runs before ads are requested and a **"Privacy options"** entry appears in Settings whenever UMP reports it is required (`PrivacyOptionsRequirementStatus.REQUIRED`) so users can change consent; no ad requests while consent says `canRequestAds == false`; premium users get NO ads and no consent prompts.
3. **Offline logic (same idea as PrankHub)**: `NetworkObserver` (Koin singleton; `isOnline(): Boolean` + `Flow<Boolean>`) based on `ConnectivityManager.NetworkCallback` (register in `OrbitApplication`-scoped lifecycle, safe unregistration). While offline: no ad/consent/remote-config requests are attempted, ad slots collapse smoothly (animate to 0dp, no empty frames/space), cached/loaded ads may still render, remote config falls back to the last fetched/defaulted values, premium purchase button shows a localized "No internet connection" message instead of calling billing, splash progress uses the short (offline) path. When the network returns, pending loads resume (observe the flow) without needing an app restart.
4. **Remote Config**: a `RemoteConfigRepository` abstraction + `AdConfig` immutable model with in-code defaults and a defaults XML (`res/xml/remote_config_defaults.xml`). Keys (all with safe defaults): `ads_enabled` (true), `banner_enabled` (true), `banner_screens` (comma list), `native_language_enabled` (true), `native_onboarding_enabled` (true), `native_exit_enabled` (true), `native_home_enabled` (true), `interstitial_splash_enabled` (false on first run, true on later runs → two keys `interstitial_splash_first_run` false / `interstitial_splash_returning` true), `interstitial_nav_enabled` (true), `interstitial_nav_every_n_actions` (4), `interstitial_min_interval_seconds` (90), `app_open_enabled` (false), `app_open_min_background_seconds` (60), `splash_max_wait_seconds` (7), `onboarding_flow_first_run` / `onboarding_flow_returning` (JSON string, parsed defensively; invalid → built-in default), `premium_close_mode` (0–3, default 2), `premium_variant_inner` (1..3). Fetch with a 7s timeout via Firebase Remote Config (min fetch interval 3s in debug, 12h in release). **Firebase is initialised manually with `FirebaseOptions` read from Gradle properties** (`orbit.firebase.apiKey`, `orbit.firebase.appId`, `orbit.firebase.projectId` → BuildConfig); there is NO google-services.json and no google-services plugin (the owner has not created a Firebase project for ORBIT yet). If those properties are blank, do not initialise Firebase at all: `RemoteConfigRepository` serves the in-code defaults (this is the state today) and the code path is documented in `docs/REMOTE_CONFIG.md` (how to create the Firebase project, which keys to publish, which properties to set). No Firebase Analytics, no Crashlytics, no FCM (keep the privacy surface minimal); add only `firebase-config` (+ BoM) dependencies.
5. **Startup flow (PrankHub logic mapped)**: extend `core/startup/InitializationHelper` steps to: settings+run count → Room warm-up → reminder reconcile → network check → **consent (UMP)** with timeout 6s (skipped if premium/offline/consent already usable) → **remote config fetch** (timeout from config, 7s) → **MobileAds initialize** (timeout 7s, skipped if premium/offline/ads disabled) → preload (language native for first run, splash interstitial if allowed, banner prefetch) → complete. Non-critical steps (everything except Room) never block longer than their timeout and never crash on failure. `SplashViewModel` progress ticker: online & not premium uses the longer path; offline/premium the short path (≈2.2s minimum); progress jumps to 100% when the splash interstitial is loaded or failed (timeout) — same idea as PrankHub; the splash must NEVER hang (hard cap `splash_max_wait_seconds + 3`). `OnboardingFlowHelper`: honour the remote JSON flow config (fall back to defaults), and implement the `SPLASH_INTERSTITIAL` step (show the loaded interstitial with a short "loading ad" overlay and a 2s safety timeout, then continue). Keep the existing language → onboarding → premium → home ordering and tests green (update tests).
6. **Managers & composables** (package `com.funsol.orbit.core.ads`): `AdsController`/`AdGate` (single place deciding "may we request/show an ad of kind X now?": premium, consent, online, remote flags, capping); `InterstitialAdManager` (preload, one-at-a-time, expiry after 1h, load timeout, capping by min interval and every-N actions persisted in memory per process, `showThen(activity) { continue }` that ALWAYS calls the continuation even on failure/timeout), `AppOpenAdManager` (ProcessLifecycle ON_START, only after min background seconds, never on cold start before Home, default off), `BannerAdSlot(placement)` (adaptive banner sized to the screen width, a reserved/animated container so the layout never jumps; collapses when disabled/offline/premium/not loaded; "Advertisement" semantics), `NativeAdSlot(placement, style: Large|Compact)` (Compose layout rendering the native ad assets with the design system: `OrbitCard` container, "Ad" pill, `MediaView` for large, icon + headline + body + CTA `GradientButton`-like button; `NativeAdView` registration done correctly; destroy on dispose; shimmer/skeleton while loading with a fixed min height so nothing jumps; hides entirely when no fill), `NativeAdCache`/pool so that Language→Onboarding transitions can reuse a preloaded ad safely (never display one NativeAd in two views at once). All callbacks switch to the main thread correctly; use `tryCatch` from `core/common/Helpers.kt` for best-effort calls; use `viewModelScope`/lifecycle-aware scopes; no leaked Activities (do not keep Activity in singletons — pass it per call or hold a WeakReference).
