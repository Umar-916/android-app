# Reference flow spec (derived from reading the PrankHub app; re-implement in ORBIT's own code and design — do NOT copy code or assets)

ORBIT adopts PrankHub's *structure and logic* but has **no ads, no Firebase, no Remote Config, no consent form, no INTERNET permission, no analytics**. Where PrankHub's step is ad/Firebase specific, ORBIT has either nothing or a generic local equivalent noted below.

## Splash + initialization (PrankHub order, ORBIT mapping)
PrankHub: `SplashVM.initializeAppAndSetupProgress` (once, guarded) → `InitializationHelper.initializeApp(activity)` = a sequential state machine: show indeterminate progress → init billing prefs → init Firebase → consent (UMP) → connect billing → fetch remote config (7s timeout) → init Mobile Ads (7s timeout) → create app-open manager → mark `appInitializationCompleted` → `onInitializationCompleted()`; then a progress ticker (1s tick, 10 steps online / 2 steps otherwise, forced to 100% when premium or interstitial loaded) sets `isLoadingComplete`; then `OnboardingFlowHelper.onboardingNavigation` decides the next screen.
ORBIT mapping (implement in `core/startup/`):
- `InitializationHelper` (a class with explicit state machine, `StateFlow<InitState>`: `Idle, Running(step, progress), Completed, Failed`): steps = (1) load settings + increment `runCount` (once per cold start, guarded so recreation does not double count), (2) open/warm the Room database (a trivial query so migrations run before Home), (3) reconcile reminders (`ReminderScheduler.reconcileAll()`), (4) apply saved language/theme readiness, (5) mark `appInitializationCompleted`. Each step has a timeout (e.g. 5s) and failure of a non-critical step must not block startup (log nothing private); a critical failure (database cannot open) must surface a friendly error state with Retry — never a crash or an infinite splash. Guard against double-run (`AtomicBoolean`). Must work when re-entered after process death/activity recreation.
- `SplashViewModel`: owns `InitializationHelper`, exposes `SplashUiState(progress: Float 0..1, isLoadingComplete, error)`; a ticker (every ~150ms for smoothness, minimum display ≈ 2.2s so the animation is seen, but never longer than the init needs + 600ms) moves progress; completes when init is done AND minimum time passed. Then asks `OnboardingFlowHelper` for the destination.
- `OnboardingFlowHelper`: decides the screen list by run count, like PrankHub: run 1 → [LANGUAGE, ONBOARDING, PREMIUM]; run 2+ → [HOME] (+ optionally PREMIUM once on run 2 if not premium and billing is available — in ORBIT premium is only shown during first run and from Settings). Config is a small in-code data structure (list of `FlowStep(type, enabled, premiumVariant)`); filter disabled/unknown, de-duplicate, skip PREMIUM when the user is premium; walk the list with an index, each screen finishing calls `continueFlow()` which navigates to the next step with `replaceTop`, and when exhausted `enterHome()`. `LANGUAGE` is skipped if `languageChosen`, `ONBOARDING` is skipped if `onboardingDone`. Replay from Settings (`Onboarding(replay=true)`) just pops back.
- Splash visuals: full-bleed gradient, big animated logo (orbit rings rotating at different speeds, glowing core, small satellite dot orbiting), app name that fades/slides in, tagline, a thin segmented progress bar and a status line ("Preparing your space…"), floating particles/stars optional; entrance is staggered (logo scale+fade 450ms, title 300ms later, footer 500ms) with the logo glow pulsing. Uses `HideSystemBars()` (immersive). Everything animated with Compose animations (no Lottie dependency, no external assets). Must look premium and attract the user.

## Language screen (PrankHub)
Top bar "App language" (+ back arrow only when Home has been reached) and a pill "Done" button at the end of the bar; body = "Selected language" header + current card, then "All languages" and a list of cards: 16dp radius, 52dp height, hairline border, flag in a 32dp circle with a thin ring, native/name text, 18dp radio drawn on a Canvas (ring 1.6dp, inner dot 22%); the highlighted (currently chosen) card is filled with primary and white text. Selection is held in the ViewModel and applied when Done is pressed (confirmSelection saves it, then applies). During onboarding applying does not need to recreate the activity; afterwards it recreates (AppCompat). Flags: use regional-indicator emoji flags (no assets). Catalog: code, English name, native name, flag emoji, `isRtl`.

## Premium flow (PrankHub)
Four art-page variants (here 3: "Aurora", "Nova", "Eclipse"); variant chosen by the flow config during onboarding and by remote value for in-app entries (ORBIT: constant 1 for in-app, flow config for onboarding). Layout of the main variant: themed background, hero image area, big title (26sp bold), price line, a bordered "What's included" card with 5 feature rows, optional trial toggle card, a plan card, terms text and a pinned bottom Continue button (height 54, radius 30, glow, arrow nudging 0→4dp over 700ms reverse). A dark immersive variant (black background, hides system bars, 3 feature rows with 36dp circle icons) and a full-art variant. **Close behaviour** (`backPressOnPremiumScreen`): after Home has been reached, back is always enabled with the close button at the start (left); during onboarding: 0 = hard paywall (no close, back disabled), 1 = close at the end immediately, 2 = close at the end after 3s, 3 = close at the start after 3s. The close button is 24dp in a 20%-black circle. Purchase flow: Continue → if offline toast; else `subscribe`; success callback flips `isPurchased` → screen's `LaunchedEffect(isPurchased)` calls `onClose()`. Entitlement is read through `isPremiumUser()` which hides the PRO pill, upgrade card, etc. PrankHub has NO restore button (implicit restore on billing client ready) and renders the literal "null" when the price is missing (a bug — never do that).
**ORBIT rules (non-negotiable, from the product brief):** no fake purchase UI. Implement `BillingProvider` (interface: `isAvailable`, `price: StateFlow<String?>`, `purchase(activity)`, `restore()`, `isPurchased: StateFlow<Boolean>`) with a default `UnavailableBillingProvider` (isAvailable=false) because `AppConfig.PREMIUM_PRODUCT_ID` is blank and Play Billing is not configured. Premium screens are fully designed and functional in structure; when billing is unavailable they honestly show "Purchases are not available yet" and the Continue button is replaced by a disabled/closing "Maybe later" action — never a working-looking Buy button, never a made-up price (hide the price line when `price == null`). Document the integration point (where a real Play Billing provider plugs in and which DataStore flag `isPremium` it must set) in KDoc and in README. The free app stays fully usable; premium never gates essential features.
`PremiumViewModel` holds state (`selectedVariant`, `price`, `isPurchased`, `trialEnabled`), `isPremiumUser()` helper reads `SettingsStore.isPremium`.

## Settings screen (PrankHub structure)
Top bar title, scroll column on background, 16dp horizontal padding. Order: (1) Upgrade-to-Pro card (88dp, gradient, crown tile, CTA pill; hidden for premium users) → opens premium; (2) "Preferences" grouped card: App language (value = current language name), App theme (value = System default/Light/Dark), notifications switch; (3) "Support & feedback" card: Rate us, Feedback, Share app; (4) "Legal"/data card: Privacy policy (+ ORBIT extras: Backup & restore, Customize dashboard, Replay onboarding, About). Section titles are small grey semibold labels ABOVE the card (outside). Row = 42dp gradient icon tile + title (14sp medium) + optional grey value + chevron; rows separated by hairline dividers inside one card (18–20dp radius, hairline stroke); switch rows use a Material Switch (white thumb, primary track). All clicks go through a 600ms click guard. Only one dialog open at a time.

## Dialog / bottom-sheet structure (PrankHub)
All dialogs are floating bottom sheets (Dialog with `usePlatformDefaultWidth=false`, card pinned to the bottom, 8dp side margins, 22–24dp radius), with a 42×3dp drag handle and a dimmed scrim. **ThemeDialog**: title (18sp bold), three option rows (52dp, 16dp radius, "well" fill, 30dp icon tile + label + 18dp radio; selected row has a 0.9–1dp primary border), selection kept in a temp state, two buttons side by side with 12dp gap: Cancel (outlined/well) and Apply (filled primary with glow); Apply saves the theme and closes, Cancel/outside tap dismiss. **RateUsDialog**: a surface with a 110dp circular icon badge overlapping its top edge, close "X" top-end, title (20sp bold primary), tagline (16sp semibold), description (12sp), 5 tappable stars with a thank-you line, Submit button (radius 40, height 50, enabled only when rating > 0, glow). Behaviour in ORBIT (fixing PrankHub's bugs: it launched the store twice on 5 stars and could crash without a Play Store): 4–5 stars → open the store listing ONCE via `openInPlayStore()` (market:// then https then toast), mark `ratePromptDone`; 1–3 stars → thank the user and (if `AppConfig.FEEDBACK_EMAIL` is set) offer the Feedback screen instead of the store. **Exit confirmation** is a bottom sheet ("Leave ORBIT?" with Exit / Stay) — already implemented in the shell.

## Feedback screen (PrankHub)
Top bar; optional banner; Issues/Suggestions toggle; description card (≈125dp, 15dp radius); "Select item" label + 2-column grid of 8 chips per tab (max 3 selections, then a message); Submit pill (radius 30, height 52, enabled with ≥1 chip) → builds a `mailto:` intent with device/app info + selections. Switching tabs clears selections. ORBIT: recipient = `AppConfig.FEEDBACK_EMAIL`; the Feedback row is hidden when it is blank; if no mail app exists show a friendly message. Do not include any user content (tasks/notes) in the email — only device model, Android version, app version and what the user typed.
